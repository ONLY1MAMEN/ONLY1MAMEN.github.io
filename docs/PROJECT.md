страницами ABOUT и CONTACT и (в планах) приватной админкой.

- Репозиторий: `ONLY1MAMEN/ONLY1MAMEN.github.io`, ветка `main`, GitHub Pages публикует её корень

Владелец не программист. Объяснять простым языком, не просить писать или править код.
Работать строго по этапам из ТЗ и после каждого этапа ждать явного подтверждения.

## Утверждённая архитектура

Один сервис и один аккаунт — GitHub. Без банковской карты, без базы данных, без Cloudflare.

- **Почему не Cloudflare:** в России соединение с сайтами за Cloudflare обрывается после первых 16 КБ.
  Vercel и Netlify частично блокируются у мобильных операторов. Yandex Cloud требует карту.
- **Публичный сайт:** статические файлы в этом репозитории, GitHub Pages.
- **Данные сайта:** один файл `data/site.json`. Страницы собираются из него заранее (не в браузере посетителя).
- **Закрытое хранилище (ещё не создано):** второй, приватный репозиторий в том же аккаунте —
  рабочая копия данных: черновики, скрытая карточка релиза, тексты отключённых страниц.
  В публичный репозиторий попадает только опубликованное.
- **Админка (этап 4):** статическая страница `/admin` на этом же сайте. Работает с GitHub напрямую из браузера.
- **Вход в админку:** ключ GitHub с точечными правами (fine-grained token) только на два репозитория сайта,
  только чтение и запись файлов. Хранится в «Паролях» iPhone, в браузере — только в памяти открытой вкладки.
- **Резервные копии:** история версий репозитория + кнопки «Скачать копию» и «Восстановить из файла».
- **Смена релиза:** в браузере посетителя, по точному мировому времени, со сверкой часов по серверу.

### Условия владельца для админки (обязательны)

1. Не обещать работу Face ID и автозаполнения ключа, пока это не проверено в Safari на iPhone.
2. Безопасная публикация: если загрузка фото или обновление данных не удались,
   публичный сайт остаётся в предыдущем рабочем состоянии.
3. Не полагаться на точность серверного времени без проверки (измерено: около 1 секунды, см. ниже).
4. Не сохранять ключ GitHub в localStorage, sessionStorage и публичных файлах.
5. Черновики никогда не попадают в публичный репозиторий до публикации.
6. Админка mobile-first: владелец управляет сайтом с iPhone в Safari.
7. Расположение блоков в админке не редактируется, только содержимое и видимость.
8. Порядок ссылок меняется стрелками ↑↓, а не перетаскиванием.

### Известные ограничения (владелец о них знает)

- Изменения появляются у посетителей через 1–10 минут после публикации (кэш GitHub Pages).
- Репозиторий публичный. Мультиссылка «Слушать», добавленная заранее, лежит в публичных файлах до релиза,
  хотя на странице не показывается.
- Ключ GitHub может потребовать обновления раз в год.
- Проверка загружаемых фото выполняется в браузере владельца, отдельного сервера нет.

### Как изменить сайт сейчас (до появления админки)

1. Поправить `data/site.json` (или шаблоны/стили).
2. Запустить `node src/build.mjs` в корне репозитория.
3. Закоммитить и отправить в `main`. Через 1–3 минуты GitHub Pages опубликует.

### Как устроены страницы

- HTML собирается заранее из `data/site.json`; страница видна и без скриптов.
- Отключённая страница (About/Contact, либо режим `site.mode = "linktree"`) не создаётся, ссылка на неё исчезает, данные остаются.
- Ссылка показывается только если она включена, у неё есть название и корректный адрес (`http`, `https`, `mailto`, `tel`, `tg`).
- Весь текст экранируется. В биографии поддерживается только выделение `**так**`.
- Строгая политика загрузки (CSP) в каждой странице: только собственные файлы сайта, без встроенных скриптов и стилей.
  Поэтому **нельзя использовать атрибут `style` и встроенные `<script>`** — только классы и внешние файлы.
- Пути относительные, сайт переносится на любой адрес.
- К адресам `site.css` и `release.js` сборка дописывает метку версии (`?v=…`, отпечаток их содержимого).
  Без неё телефон до 10 минут показывал новую страницу со старым оформлением из кэша.
- Координаты в верхней строке: на любом сенсорном устройстве в две строки, в одну — только на компьютере с мышью (≥900 px).

### Карточка релиза

- `release.mode`: `auto` | `soon` | `out` | `hidden`.
- В `auto` момент выхода = `date` + `time` в поясе `timezone` (по умолчанию `Europe/Moscow`).
- До выхода: «Скоро релиз», дата, кнопки пресейва VK и Яндекс (показываются только заполненные).
- После выхода: «Latest release», одна кнопка «Слушать» на готовую мультиссылку (если её нет — кнопки нет).
- Сверка часов: запрос `HEAD ping.txt?t=…`, заголовок `Date` (+ `Age`, + 0,5 с на округление).
  Если до релиза или после него меньше двух суток, карточка ждёт сверку до 1,5 с, чтобы не показать неверное состояние.
- Проверено в Chrome: переключение без перезагрузки, часы устройства ±2 минуты, ручные режимы, отсутствующие ссылки (13 из 13).

## План этапа 4 (исходный, выполнен — см. раздел «Этап 4» ниже)

- Создать приватный репозиторий для рабочей копии и ключ GitHub с правами на оба репозитория.
- `/admin`: вход по ключу; разделы Главная, Ссылки, Релиз, About, Contact, Режим сайта, Оформление, История.
- Черновик сохраняется в приватный репозиторий; предпросмотр рендерится теми же шаблонами `src/render.mjs`.

- Фото: выбор из галереи, кадрирование, сжатие и нарезка размеров в браузере.
- История: список публикаций, предпросмотр версии, возврат как новая публикация.
- Скачать копию / восстановить из файла.
- Админку нельзя индексировать поисковикам; ключ нигде не сохраняется, кроме памяти вкладки.

## Правила работы с владельцем

- Не подключать платные услуги и не привязывать карту без согласия.
- Не скрывать ограничения и не выдавать заглушки за готовые функции.
- Не расширять функциональность сверх ТЗ (раздел 10 ТЗ — список того, чего быть не должно).
- Не менять главную страницу без необходимости; дизайн не переосмыслять.
- Каждому передаваемому файлу или версии давать отдельное имя с номером версии.
- Действовать только в репозиториях сайта; другие репозитории и настройки аккаунта не трогать.

## Правки после этапа 3 (16 ноября 2026)

- **Сайт «статичный»:** картинки и значки нельзя зажать, вытащить или сохранить (`pointer-events: none`,
  `-webkit-touch-callout: none`, `draggable="false"`); долгое нажатие на кнопку не открывает предпросмотр ссылки.
  Оформление не выделяется; текст биографии и адрес почты выделить можно. На iPhone владельцем ещё не проверено.
- **Карточка релиза:** строка «Новый релиз» над названием убрана (`release.kickerOut` пустой — строки нет).
- **About:** абзац про «ещё один шанс» заменён на вариант одним предложением.
- **LISTEN:** добавлены КИОН Музыка и Звук (значки взяты с сайтов площадок, приведены к чёрному силуэту).
  Показ — просто строками по две (четвёртая строка). Вариант с прокруткой внутри блока владелец отклонил, код удалён.

## Этап 4 — админка (собрана 16 ноября 2026)

Адрес: https://only1mamen.github.io/admin/ (закрыта от поисковиков; без ключа — только экран входа).

```
admin/index.html   страница админки
admin/app.js       всё управление: разделы, предпросмотр, черновик, публикация, история, копия
admin/gh.js        запросы к GitHub (чтение файлов, публикация одним коммитом)
admin/images.js    выбор фото, кадрирование, сжатие в браузере
admin/config.js    имена хранилищ: публичное ONLY1MAMEN.github.io, закрытое mamen-site-private
admin/admin.css    оформление
```

- **Вход:** ключ GitHub (fine-grained token) с правом «Contents: Read and write» на оба хранилища.
  Ключ живёт только в переменной открытой вкладки; после закрытия или «Выйти» его нет нигде.
- **Разделы:** Главная (фото, надписи, детали оформления), Ссылки (Listen/Follow: добавить, изменить, удалить,
  порядок ↑↓, скрыть, значок из набора или свой), Релиз (режим, обложка, дата/время/пояс, пресейвы, мультиссылка,
  все надписи), About, Contact, Сайт (режим, цвет фона из 7 предусмотренных, название и описание, копия, сброс), История.
- **Отмена:** кнопка «↶ Отменить» в нижней панели возвращает на шаг назад (до 60 шагов, в пределах открытой вкладки);
  «Сбросить всё к версии на сайте» — во вкладке «Сайт». Под последним полем каждого раздела оставлено место, чтобы панель его не закрывала.
- **Черновик:** «Сохранить черновик» пишет `site.json` и новые картинки в закрытое хранилище. Публичный сайт не меняется.
  Если закрытое хранилище недоступно ключу, кнопка выключена, публикация работает.
- **Публикация:** страницы собираются в браузере теми же шаблонами `src/render.mjs` и уходят одним коммитом
  (данные + страницы + новые картинки). Ветка переводится на новую версию последним шагом и без force:
  при любой ошибке сайт остаётся прежним; если сайт изменили не из админки — публикация отказывает.
  Картинки, загруженные через админку и больше нигде не используемые, удаляются из сайта (в истории остаются).
- **История:** список публикаций; старая версия открывается в редакторе и публикуется как новая (недостающие
  картинки берутся из той версии).
- **Копия:** один файл JSON с данными и картинками; восстановление загружает его в редактор.
- **Фото:** перекодируются в браузере (webp, а где браузер не умеет — jpg; `photo.format`), три ширины + запасной jpg.
  Обложка — квадрат 600×600. Свой значок — PNG 96×96.
- **Цвета:** `site.theme` — grey, light, white, warm, sand, cool, stone (заданы в `site.css` и `THEMES` в `render.mjs`).
- **Проверено** (Chrome, экран телефона, поддельный GitHub, 36 проверок): вход и отказ по неверному ключу, ключ не попадает
  в хранилища браузера, правки, загрузка фото и обложки, предпросмотр, черновик, сбой публикации не меняет сайт,
  публикация даёт страницы байт-в-байт как `node src/build.mjs`, отключение страницы, история и возврат версии,
  отказ при чужом изменении, копия, выход.
- **Не проверено:** настоящий GitHub с настоящим ключом; Safari на iPhone (выбор фото из галереи, сжатие,
  кадрирование пальцем, автозаполнение ключа из «Паролей», Face ID).
- **Известные ограничения:** несохранённые правки живут только в открытой вкладке (если Safari выгрузит вкладку —
  пропадут, поэтому «Сохранить черновик» стоит нажимать чаще); картинка для превью ссылки в мессенджерах (`og.jpg`)
  через админку не меняется; оформление самих шаблонов (шрифты, размеры, расположение блоков) — только через код.
- **Запуск (16 ноября 2026):** закрытое хранилище `mamen-site-private` создано, ключ владелец создал сам и вошёл в админку с iPhone;
  замена фото и публикация с настоящим ключом работают, зажатие картинок на iPhone пропало. Черновики владелец не проверял.
  Тестовая страница `/test/` удалена. Со слов владельца, сайт открывается у знакомого в Москве (сеть не уточнялась).
